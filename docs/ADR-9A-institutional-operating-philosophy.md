# ADR-9A — Institutional Operating Philosophy

## Purpose

Define the governing philosophy for the Trustee App as an Institutional Operating System.

## Core Principle

The platform is no longer only a trust app.

It is an institutional fiduciary operating system.

## Operating Rules

1. Institution before application.
2. Workspace before page.
3. Module before screen.
4. Record before document.
5. Engine before feature.
6. Shared services before duplication.
7. Matter and institution context before isolated action.
8. Governance, compliance, archive, and audit must be designed into workflows from the beginning.

## Institutional Flow

Institution
→ Workspace
→ Module
→ Record
→ Action
→ Evidence
→ Timeline
→ Archive

## Design Commitments

The app must support:

- Trust creation
- Matter governance
- Funding
- Execution
- Instrument registry
- Governance lifecycle
- Compliance review
- Institutional archive
- Research workspace
- Knowledge/playbooks
- Legacy/genealogy records
- Reports and evidence packages
- System security and backups

## User Experience Rule

The user should not have to hunt through pages.

The system should show:

- What needs attention
- What recently happened
- What should happen next
- Whether the institution is healthy

## Long-Term Standard

Every future feature must fit into the IOS model without creating a disconnected dashboard, duplicate navigation area, or isolated workflow.
