# IOP-1A — Institutional Intake & Matter Creation Engine

## Purpose

Unify intake, matter creation, decision review, and instrument creation into one guided institutional workflow.

The app should not begin with “Create Trust.”

The app should begin with:

Start New Matter

The trust or other instrument is created only after intake, assessment, and recommendation.

## Core Rule

Intake and Create Trust are part of the same institutional process.

However, Create Trust is not Step 1.

Matter creation and intake come first.

## Primary Workflow

1. Start New Matter
2. Institutional Intake
3. Identity / Family / Entity Review
4. Assets and Liabilities
5. Goals and Objectives
6. Risk and Governance Review
7. Existing Documents Review
8. Decision Engine Recommendation
9. Institutional Plan
10. Instrument Selection
11. Instrument Creation
12. Funding
13. Execution
14. Governance
15. Archive

## Instrument Creation Rule

Instrument creation must not be limited to a fixed list.

The system must support:

- Recommended Instruments
- Optional Instruments
- Custom Instruments
- Other Instruments
- Future Instrument Types
- User-added Instruments
- Admin-added Instrument Templates

### Custom / Other Instruments

The system must allow the user or admin to add instruments not already listed.

Each custom instrument should capture:

- Instrument Name
- Instrument Category
- Purpose
- Matter ID
- Linked Trust ID, if applicable
- Required Signers
- Required Witnesses
- Notary Required
- Funding Related
- Execution Related
- Archive Required
- Notes
- Status

## Decision Engine Requirement

The Decision Engine should recommend instruments based on:

- Matter type
- Family structure
- Asset profile
- Risk level
- Trust goals
- Existing documents
- Special assets
- Business ownership
- Life insurance
- Pets
- Firearms
- Real property
- Legacy / genealogy needs

## Institutional Plan Output

Before documents are generated, the system should produce an Institutional Plan containing:

- Matter summary
- Recommended structure
- Recommended instruments
- Optional instruments
- Custom instruments
- Funding priorities
- Execution requirements
- Governance requirements
- Archive requirements
- Warnings and unresolved issues

## Design Principle

The app should never force the user into one trust template too early.

The system should first understand the matter, then recommend the correct institutional structure.
